# 交接文档：shopping-harness-longhorizon

> 面向接手的后续开发者。本文件概括项目目标、架构、已实现内容、尚未实现内容、
> 关键命令与安全红线。截至 2026-08-21。

---

## 1. 项目目标（研究问题）

基于 **DeepSeek Harness（DSH）** 与内嵌的 **ShopSimulator**，构建一个
**"无训练" Self-Harness 购物 Agent** 原型：

- 固定 Agent 模型权重（不做 SFT / GRPO / LoRA，不训练模型，也不训练独立的
  harness engineer）；
- Agent 在 ShopSimulator 中执行购物任务，记录失败轨迹；
- 后续由**同一个冻结模型**基于失败轨迹提出受限、可验证、可回滚的 harness 修改；
- 进化只发生在 **harness 层**（system prompt / tool surface / 策略 / overlay），
  绝不改环境、Reward、模型权重或 DSH 源码。

当前进度：**h0 基线 + 双轨迹记录 + 批量 baseline evaluator 已完成**；
Self-Harness 闭环（failure mining → proposer → candidate → gate → promotion）
**尚未开始**。

## 2. 关键架构与硬性边界

### 冻结层（禁止修改）

| 层 | 位置 |
|---|---|
| DSH 源码 | `dsh/`（固定 SHA，见 DEPENDENCIES.md） |
| ShopSimulator 环境 | `environment/ShopSimulator/`（vendored snapshot） |
| HTTP adapter / session | `plugins/shopping/src/environment/` |
| primitive action grammar | `search[...]` / `click[...]` / `finish[...]` |
| harness 加载/校验基础设施 | `plugins/shopping/src/harness/` |
| guard + DSH 注册装配 | `plugins/shopping/src/tools/` |
| 观测投影 | `plugins/shopping/src/observation/` |
| 轨迹审计 / task source / evaluator | `plugins/shopping/src/rollout/` |
| actor/evaluator 双轨迹隔离 | 结构性：reward 只在 evaluator 侧，绝不回灌模型 |
| 模型权重与连接 | 连接配置只在本地 `.env` |

### 可编辑层（未来 Self-Harness candidate 的修改对象）

- `harnesses/*/system-prompt.md`
- `harnesses/*/tool-surface.yml`
- `harnesses/*/runtime-policy.yml`
- `harnesses/*/verification-policy.yml`
- 明确声明的 Cordis overlay 配置键

> 注意：**harness 的 YAML/md 内容**才是 candidate 可修改对象；plugin 的
> tool-surface resolver / schema validator 是冻结基础设施。

### h0 三个 primitive 工具

| 工具 | primitive | 冻结映射 |
|---|---|---|
| `shop_search({ query })` | search | `search[query]` |
| `shop_click({ target })` | click | `click[target]` |
| `shop_finish({ reason })` | finish | `finish[no_suitable_product]` |

- 工具名/schema/描述的**唯一配置来源**是 `harnesses/base/tool-surface.yml`；
  plugin 不硬编码工具名。
- `shop_click.target` 必须来自模型上一轮实际看到的当前页面可点击项（冻结 guard，
  历史页面 target 天然失效）。
- 旧 12 个高层语义工具（open_product / buy_now / 翻页 / 查看子页等）已废弃，
  不属于 h0；未来只能作为 candidate harness 的高层表示出现，且不得改环境映射。

## 4. 已实现内容（按阶段）

1. **脚手架与依赖固定**：DSH clone 固定 SHA、ShopSimulator vendored snapshot、
   DEPENDENCIES.md。
2. **ShopSimulator 独立启动 + HTTP smoke**：`scripts/setup_environment.sh` /
   `start_environment.sh` / `smoke_environment.py`。
3. **environment adapter**：protocol/client/session（四类错误、会话生命周期、
   withSession finally）。
4. **DSH 接入**：bundle + profile 机制，`ctx.tools.register`，check:dsh 离线校验。
5. **live runner**：`.env` + `--live` 显式授权；`scripts/run_live_task.sh`。
6. **bootstrap 时序修复**：runner 单次 reset → instruction 注入 DSH 初始 prompt
   → plugin 接管同一 env_idx（绝不二次 reset）。
7. **bootstrap 生命周期加固**：按 run 隔离 `.live/runs/<run_id>/bootstrap.json`、
   原子 no-clobber 写入（O_EXCL + fsync + linkSync）、结构化错误、recovery record、
   runner→launcher→DSH 信号转发、cleanup 幂等（release_one，绝无 release_all）。
8. **h0 三原语 + canonical harness 表示**（harness.yml 等五文件 + surface loader）。
9. **固定 development benchmark + 批量 baseline evaluator**：
   `configs/evaluation/development-v1.yml`（held-in 0-7 / held-out 8-11）、
   `scripts/validate_development_tasks.py`（无模型发现/验证）、
   `scripts/run_h0_baseline_eval.sh` + `scripts/baseline_orchestrator.ts`
   （批量运行、独立 run_id、聚合脱敏结果）。

## 6. 关键命令

```bash
bash scripts/setup_environment.sh          # 首次：venv + 解压数据 + 建索引
```



## 7. 数据与安全红线

- **绝不修改** `dsh/`、`environment/ShopSimulator/`、模型权重、Reward、任务定义。
- **Final-200 Clean** 仅作未来最终盲测；绝不用于 failure mining、patch 生成、
  调参或候选选择。本项目**不宣称**与 Final-200 集合不相交（其构成在本仓库未知）。
- 不依赖 `shopping-grpo-longhorizon` 的任何运行时/训练/数据。
- **actor trace 与 evaluator record 严格隔离**：reward 只经 client 的
  `evaluatorSink` 流向 evaluator record，工具结果/prompt/session 在类型上
  拿不到它，绝不回灌同一任务模型。
- 结果文件绝不含：API key、goal、gold、reward（actor 侧）、完整原始 observation、
  隐藏 purchase 信息、任务指令原文（除 actor trace 中模型实际看到的部分）。
- `.env`、`.live/`、`trajectories/`、`evaluation/runs|baselines/` 全部 gitignored。
- bootstrap / recovery record 只含 actor-safe 字段：schema_version、run_id、
  task_id、env_idx、instruction_text（0600、no-clobber）。

- `scripts/baseline_orchestrator.ts` — 批量聚合与结果语义
